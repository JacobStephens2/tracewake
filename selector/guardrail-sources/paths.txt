# The paths that run unattended (#165, spec #151 story 34).
#
# One path per line, repository-relative; comments and blank lines ignored.
# `guardrail-sources/protection.sh` compares each of these in the DEPLOYED TREE
# against the protected ref, and the guardrail chip on /loop is red while any
# of them differs. This file is the declaration that chip is built on, and it
# lives inside one of the paths it declares - so widening or narrowing it is
# itself a reviewed change.
#
# The test for inclusion is narrow on purpose: does a timer with nobody
# watching, or model output, execute this? The rest of the repository is a
# working area, and a guardrail that went red for a report page is one nobody
# could keep green.

# The Loop's scripts. Executed on the box, and placed there by
# `deploy/ansible/roles/loop_scripts`, which copies them out of THIS tree
# rather than out of a merge - so what is sitting here is what the next apply
# deploys.
loop

# The Selector itself: the cycle systemd starts every thirty minutes, the
# dispatch that seeds a branch and starts a Run on the box, the watcher, the
# Journal, and this declaration.
selector

# How that cycle is invoked: the units and the timer. The wrapper named in the
# unit's ExecStart resolves the instance's credentials and so lives in the
# instance's own tree, not this one - guarding it needs the multi-tree
# Guardrail, which is a ticket of its own.
deploy/systemd/tracewake-selector-cycle.service
deploy/systemd/tracewake-selector-cycle.timer

# And how the operator is told about it: the notifier's unit (ADR 0018). It
# runs unattended for the same reason the cycle does, and it is the only thing
# that speaks when a Run fails - an unreviewed edit here is an alarm that goes
# quiet without anything failing to say so.
deploy/systemd/tracewake-selector-notifier.service
